# 检索问答工作流细节

## ① 解析意图

从用户问题中提取：

| 要素 | 示例 | 映射 |
|------|------|------|
| 核心关键词 1-3 个 | "知识库里有没有关于 RAG 的笔记" → `rag` / `检索增强` | search.query |
| 类型意图 | "看下归档的原文" → archive | search.type |
| 标签意图 | "会议纪要里提过吗" → `会议` | search.tags |
| 时间意图 | "最近记的" | search 结果按 updated_at 排序后取最新 |

**不要**把整句话塞进 query（"知识库里有没有关于RAG的笔记" 会要求所有字都命中）——先提词再检索。

## ② 召回策略

1. 首选 1 个最核心的 ≥3 字中文短语或英文词
2. 0 命中 → 换同义词/上位词重试一次（"排期" → "项目计划"；"分词器" → "trigram"）
3. 仍 0 命中 → 明确告诉用户 + 问"是否现在整理入库？"（用户给了材料就转 library-organize 流程）
4. 召回 >5 篇且前几篇 snippet 都不相关 → 加一个关键词 AND 收紧

## ③ read 的取舍

- 只 read 与问题**直接相关**的候选（snippet 判断），通常 1-3 篇
- 看标题/snippet 就能回答的（简单事实）不必 read
- read 返回 content 全文 + links；注意 links 指向的关联笔记可能也值得跟进（最多跟进一层）

## ④ 综合整理

- **综合而非罗列**：多篇笔记的观点要融合成一个连贯回答
- **标注演进**：`doc_001`（9月10日）认为 X，`doc_002`（9月12日）修正为 Y——按 updated_at 判断新旧
- **指出矛盾**：笔记间冲突时如实呈现两说 + 各自 doc_id，不擅自裁决
- **引用精确**：引用具体数据/结论时先 read 原文核对，不凭 snippet 断章取义

## ⑤ 追问选项（卡片结尾）

按场景给 2-3 个：
- "需要我展开某一篇全文吗？"
- "换个关键词再查？"
- "按时间排序看看最近的？"
- （0 命中时）"要不要现在整理入库？"

## 边界情况

| 情况 | 处理 |
|------|------|
| 用户问"我知识库里都有什么" | `list`（不带 query），按 updated_at 倒序展示标题清单 |
| 用户给出精确 doc_id | 直接 `read`，跳过 search |
| 用户要删除 | 提示需要 ALLOW_WRITE + ALLOW_DELETE 双开；开启时先展示内容再确认（本 skill 不主动删） |
| 用户要修改已有笔记 | MVP 无 update 工具：read 旧笔记 → 生成新整理稿（links 指向旧篇）→ write 新篇；旧篇如需删除走 delete |
