# 查询模式速查

## trigram 分词的行为模型

理解这些行为才能预判召回：

| 查询 | 能否命中 | 原因 |
|------|---------|------|
| `知识库设计`（≥3 字） | ✓ 子串命中《个人知识库架构设计》 | trigram 3 字滑窗索引 |
| `检索增强` | ✓ 命中《RAG 检索增强生成》 | 同上，中英混排不受影响 |
| `rag` | ✓（≥3 字符） | 英文同样 trigram |
| `排期`（2 字） | ✓ 但排后 | 走 LIKE 兜底（score=100） |
| `ai`（2 字符） | ✓ 但排后 | 同上 |
| `知识库 检索`（空格分词） | ✓ AND 语义 | 两词都要出现 |
| `"知识库"`（带引号传入） | ✓ | 保留字符自动剥离 |

## 常见问答 → 检索转换

| 用户说 | search 参数 |
|--------|------------|
| "有没有关于 X 的笔记" | `{query: "X"}` |
| "之前怎么解决 Y 问题的" | `{query: "Y"}` → 0 命中试 `{query: "Y 解决"}` |
| "客户A 都聊过什么" | `{query: "客户A"}`；或 `{tags: ["客户a"]}` 配宽 query |
| "归档的原文里有没有 Z" | `{query: "Z", type: "archive"}` |
| "最近记了什么" | `{}`（用 list，按 updated_at 倒序） |
| "库里都有什么类型的笔记" | `{}`（list + 汇总 type/tags 分布） |

## 放宽与收紧

- **收紧**（召回太多且前几不相关）：query 加一个关键词 AND；或加 type/tags 过滤
- **放宽**（0 命中）：
  1. 同义词：`排期` → `计划`、`分词` → `trigram`、中英互换
  2. 上位词：`飞书多维表格` → `多维表格` / `bitable`
  3. 拆词：`客户A项目排期` → `客户A`
  4. 每次只放宽一个维度，最多两轮——仍 0 命中如实告知

## 结果不足时的补充手段

- search 的 tags 过滤在排序**之后**做（先 FTS/LIKE 召回再过滤），tags 太偏可能把结果滤空——tags 过滤 0 结果时去掉 tags 用纯 query 再试
- 想看某篇的关联笔记：read 它 → 拿 links 里的 doc_id 继续 read
- 想全库找标签：`list` + tags 过滤（不依赖全文命中）
