# 知识库检索问答（library）

> 📌 **回答纪律**：
> 1. **答案必须带 doc_id 引用**：每条结论标注来源（`doc_2026-09-12_001`），用户可随后 `read` 深入
> 2. **0 命中就明说**："知识库中暂无相关内容"，并问"是否现在整理入库？"（转到整理流程），绝不编造笔记内容
> 3. **多笔记综合**：召回多篇时整合观点、指出演进（哪篇更新），不是简单罗列
> 4. 检索默认只查未删除文档；`snippet` 里 `⟨⟩` 包裹的是命中上下文

## 1. 工作流总览（五步）

```
① 解析意图 → ② search 召回 → ③ read 候选 → ④ 综合整理 → ⑤ 卡片回复 + 追问
```

| 步骤 | 动作 | 要点 |
|------|------|------|
| ① 解析意图 | 提取关键词 | 从问题里提 1-3 个实质词（≥3 字中文短语召回最好）；识别可选过滤（type/tags） |
| ② search | `mcp__library__search` | top_k=5；0 命中 → 换同义关键词放宽重试一次，仍 0 → 明说并引导入库 |
| ③ read | `mcp__library__read` | 只 read 与问题真正相关的 1-3 篇（snippet 判断），不要全读 |
| ④ 综合 | Claude 整理 | 融合多篇观点，标注每条来源 doc_id，指出笔记间的演进/矛盾 |
| ⑤ 回复 | `send_text` 卡片 | 标题 + 直接回答 + 要点（带来源）+ "是否深入？" |

## 2. 查询构造（trigram 特性）

- 中文 **≥3 字**的短语直接子串命中：问"检索增强"能召回《RAG 检索增强生成调研》——用自然短语，不用拆字
- 2 字短词（如"排期"）走 LIKE 兜底，也能命中，但排序靠后
- 多关键词 AND：`"embedding 检索"` 要求两者都出现；召回过少时拆成单关键词
- 英文大小写不敏感；`" ' ( ) * : ^` 会被自动剥离，不用预处理

更多模式（0 命中放宽、按标签/类型过滤、时间排序）：[references/query-patterns.md](references/query-patterns.md)

## 3. 回复卡片格式

```markdown
🔍 知识库检索：{原问题}

**直接回答**
{1-3 句综合结论}

**相关笔记**（{N} 篇）
1. 《{标题}》 `doc_2026-09-12_001`
   {一句该笔记的核心观点}
2. ...

**要点**
- {带 doc_id 引用的结论}
- {观点演进：doc_002 在 doc_001 基础上修正了 X}

需要我展开某一篇全文 / 换关键词再查吗？
```

## 4. 工具速查与错误

工具参数细节：[references/mcp-tools.md](references/mcp-tools.md)

| 现象 | 处理 |
|------|------|
| EMPTY_QUERY | 关键词清洗后为空，换实质词 |
| 0 命中（无错误） | 同义词放宽一次 → 仍 0 则明说 + 问是否整理入库 |
| DOC_NOT_FOUND | 召回的 doc_id 已被删除，重新 search |
